### BUG-2026-07-12b — default input value fires on a connected port, reversing work-log feed order

| Field                  | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| ---------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **Date**               | 2026-07-12                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Area**               | execution · runtime · feed                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Status**             | fixed                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Symptom**            | In the example workflow (`string → router → delay(1000) → preview → finish`) the work-log feed ended `finish → preview → common-delay` in reverse; the delayed value (`"Hello"`) leaked into the feed _after_ `done`.                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| **Repro**              | Run `demo-project/.langflower/workflows/example.json`. `delay` has `defaultValue: 0` but its real delay arrives via an edge from a `number(1000)` node (through the router).                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Root cause**         | `materializeRuntimeNode` seeds every port default (`defaultInputsFromDefinition`) via `input.connect(of(value))` **unconditionally at node-add time**. At run start `wireScope` wires the real edge on top, but the seeded `0` is already on the connection, so `combineInputs([value, delay])` fires at t≈0 with `delay=0` → premature `of(value).pipe(delay(0))` → `preview` → `finish(stopsRun)` → `done`. The real `delay=1000` emission then arrives after `done`, producing the reversed tail. The runtime's own `applySeeds` already skips wired slots, but server-side default seeding bypassed that guard because it occurs at materialization, before the run. |
| **Fix**                | `runtime-runner.ts` `wireScope` now clears a seeded default on every input port an edge will drive — a pre-pass calls `connection.disconnect()` on each wired target **before** any edge is wired. A wired port is then sourced solely from its edge (combineLatest waits for the real value, so no early fire); an unconnected port keeps its seeded default. Harness/manual `connect`s on unwired ports are untouched.                                                                                                                                                                                                                                                 |
| **Design flaw signal** | **Default value applied even when the port is connected.** A port `defaultValue` is design-time metadata for the _unconnected_ case, but it was injected as a live connection value at materialization and never revoked when an edge superseded the port — a "default vs. actual" ownership mismatch at the runtime boundary. Rule: a default may drive a port **only when nothing is connected to it**.                                                                                                                                                                                                                                                                |
| **Regression test**    | `packages/runtime/src/testing/workflows/default-value.workflow.test.ts` — wired port drops the seeded default (output delayed by the edge); unconnected port keeps the default (immediate).                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
