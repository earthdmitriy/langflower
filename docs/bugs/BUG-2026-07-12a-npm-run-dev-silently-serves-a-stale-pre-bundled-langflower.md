### BUG-2026-07-12a — `npm run dev` silently serves a stale pre-bundled `@langflower/shared` after a rebuild

| Field                  | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| ---------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Date**               | 2026-07-12                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Area**               | ui · build                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                              |
| **Status**             | fixed                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| **Symptom**            | Browser console: `Uncaught SyntaxError: The requested module '/@fs/.../.angular/cache/.../vite/deps/@langflower_shared_langflower.js?v=...' does not provide an export named 'resolveUiSchemaOptions'` even right after `npm run dev` rebuilt every package (including `@langflower/shared`) and the new export was verified present in `packages/shared/dist/langflower.js`.                                                                                                                                                                                                           |
| **Repro**              | Add a new export to `@langflower/shared`'s entry module, import it from a `packages/ui` component, run `npm run dev` (which does a fresh `build-all` first), open the app — the import fails even though `dist/` is correct and `ng serve` recompiled with zero TS errors.                                                                                                                                                                                                                                                                                                              |
| **Root cause**         | Angular's Vite-based dev server pre-bundles `node_modules`/workspace dependencies and caches the bundles on disk at `packages/ui/.angular/cache/<version>/ui/vite/deps/`. That cache's invalidation key does not account for a local workspace package's `dist/` being rewritten in place (no `package.json`/lockfile change) — so a `dev.mjs` restart kept reusing the pre-rebuild `@langflower_shared_langflower.js` bundle, silently missing the new export until someone thought to delete the cache by hand.                                                                       |
| **Fix**                | `build/dev.mjs` now deletes `packages/ui/.angular/cache` after `build-all` and before starting `ng serve`, forcing Vite to re-optimize dependencies from the fresh build on every `npm run dev` invocation. (`build/clean.mjs` already removed this same directory, but that command is never called automatically as part of the normal dev loop.)                                                                                                                                                                                                                                     |
| **Design flaw signal** | **Cache invalidation blind to an out-of-band write.** A disk cache keyed off a coarse signal (lockfile/package.json hash) silently went stale when the thing it cached (`dist/`) was rewritten through a different path (a local build step) that the cache's own invalidation logic never observes. Any tool that pre-bundles/caches workspace-linked packages needs either its cache cleared by the same pipeline that rebuilds those packages, or a `--force` re-optimize flag wired into that pipeline — never left to be discovered per-developer after a confusing runtime error. |
| **Regression test**    | none — this is a dev-tooling cache-invalidation issue, not app logic; covered by the `dev.mjs` change itself (cache clear runs unconditionally on every `npm run dev`) rather than a test                                                                                                                                                                                                                                                                                                                                                                                               |
