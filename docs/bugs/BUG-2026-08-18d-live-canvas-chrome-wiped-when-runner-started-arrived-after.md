### BUG-2026-08-18d — Live canvas chrome wiped when `runner.started` arrived after ports

| Field                  | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Date**               | 2026-08-18                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Area**               | runtime · ui · ws                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |
| **Status**             | fixed                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Symptom**            | Run test review-gate, Stop while the gate is still pending: canvas went idle (no amber). Refresh replayed the snapshot and showed pending chrome. Feed/chrome treated `runner.started` as a new run and wiped live prefix frames.                                                                                                                                                                                                                                                               |
| **Repro**              | Start a graph with a long pending node. NDJSON: `runner.port` `{ pending: true }` then `runner.started`. Stop before the node settles. Live canvas idle; reload shows amber.                                                                                                                                                                                                                                                                                                                    |
| **Root cause**         | `RuntimeRunner.runScope` wired the graph (port taps fire) **then** returned `runId`. The server emits `runner.started` only after `start()` returns, so ports raced ahead. UI folds keyed a new-run wipe on `started` when `runId` was still `null` (port 7-tuples carry no runId). Snapshot replay has no that wipe.                                                                                                                                                                           |
| **Fix**                | `runScope` assigns `runId` and `'running'` synchronously, then `queueMicrotask` → `wireScope`. `interrupt` / `dispose` cancel a pending wire. Callers keep `start()` then `bridgeEmit(started)`. Chrome / HITL / feed reset **adopts** `null → runId` instead of clearing.                                                                                                                                                                                                                      |
| **Design flaw signal** | Returning from `start()` after side-effect telemetry makes every `started`-after-`start()` caller lose the fence. Run identity must exist before the first port, and live folds must adopt an unknown `runId` instead of treating `started` as “wipe and begin”.                                                                                                                                                                                                                                |
| **Regression test**    | `packages/runtime/src/testing/workflows/start-wire-defer.workflow.test.ts`; `tests/integration/ws/pending-events-bridge.ws.test.ts` (`started` before first `port`); `execution-chrome-fold.test.ts` / `canvas-node-status-projection.test.ts` / `canvas-node-hitl-projection.test.ts` / `execution-feed.service-lifecycle.test.ts` (ports then reset `null→id` keep pending); `packages/ui/src/app/features/canvas/tests/node-preview-values.service.test.ts` (`null→runId` keeps live inputs) |
