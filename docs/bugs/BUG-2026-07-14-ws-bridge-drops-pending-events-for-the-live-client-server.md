### BUG-2026-07-14 — WS bridge drops `pending` events for the live client (server subscribes to `runner.events$` after run start)

| Field                  | Value                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| ---------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Date**               | 2026-07-14                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                       |
| **Area**               | execution · runtime · server · ui                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Status**             | fixed                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Symptom**            | A client already connected when the run starts sees no yellow "pending" indicator on reactive nodes such as `common-delay`. The work log / canvas chrome go straight from `inactive` to `value` on that live client; the `pending` pulse the UI uses for `nodeStatus === 'pending'` is never delivered over the WS bridge on the live path. Clients that connect _after_ the run has started do see the pulse (they replay the `executionFeed` snapshot), which masked the defect. The nodes themselves emit `pending` correctly — proven by `forward-runner-event.test.ts`.                                                                                                                                                                                     |
| **Repro**              | Connect a WS client, wire `constant → common-delay(1000) → finish`, run, and watch `runner.output-emitted` for the delay node: the live client receives only `state: 'value'` (no `pending`). A client connecting after the run already started receives `pending` then `value` (snapshot replay). Compare with `packages/server/src/bridge/forward-runner-event.test.ts` which exercises the bridge subscription directly.                                                                                                                                                                                                                                                                                                                                      |
| **Root cause**         | The reported bug (pending never delivered over the WS bridge on the live path) was a **server-side subscription race**: `attach-langflower-bridge.ts` subscribed to `runner.events$` only _per client_ at connect time, _after_ `runner.start()` had already fired the initial `pending` events into that `events$` — a plain, non-replaying RxJS `Subject`. Those emissions were dropped on the live path; clients connecting afterwards masked the loss by replaying the `executionFeed` snapshot. The library, runtime, and node definitions (including `common-delay`) emit `pending` correctly — proven by `pending-state.workflow.test.ts` and `forward-runner-event.test.ts`; the defect was purely the bridge subscription timing, not the node pattern. |
| **Fix**                | Server: `attach-langflower-bridge.ts` now holds a single always-on subscription to `session.runtime.runner.events$` (independent of clients/runs), fanning out to all connected clients via the existing `clientIndex`; re-subscription only if the runner instance changes (it is a stable singleton across runs and workflow loads — `loadWorkflowIntoSession` rebinds the same editor instead of recreating the runner). No replay buffer; late clients still receive the backlog through the existing `executionFeed` snapshot. No node-definition change was needed — the nodes already emit `pending`.                                                                                                                                                     |
| **Design flaw signal** | **Event-stream subscription timing vs. source lifecycle.** A plain (non-replaying) RxJS `Subject` used as the run's telemetry bus drops every emission that occurs before a subscriber attaches. The telemetry subscription must be established _before_ the run starts (or be always-on) — otherwise initial events are silently lost even when the source emits them. The node/definition layer was not at fault; the loss was entirely on the subscription-boundary side.                                                                                                                                                                                                                                                                                     |
| **Regression test**    | `tests/integration/ws/pending-events-bridge.ws.test.ts` — `single always-on subscription fans pending out to all connected clients` (the server fix) and `delay node emits pending then value through bridge` (over the real WS bridge). `packages/runtime/src/testing/workflows/pending-state.workflow.test.ts` — runtime emits `pending` for every node type in the harness. `packages/server/src/bridge/forward-runner-event.test.ts` — `pending` `output-emitted` events reach the bridge client.                                                                                                                                                                                                                                                            |
