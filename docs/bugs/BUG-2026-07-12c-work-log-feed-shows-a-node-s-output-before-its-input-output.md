### BUG-2026-07-12c — work-log feed shows a node's output before its input (`output-emitted` precedes `input-received`)

| ---------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Date**               | 2026-07-12                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Area**               | execution · runtime · feed                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Status**             | fixed                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Symptom**            | Two ordering symptoms in the work-log feed, both from the same cause: (1) per node, `output-emitted` appeared **before** `input-received`; (2) in the `string → delay(1000) → preview → finish` example the delayed node's **section** landed **last** (`finish → preview → delay`) — the delayed value reached the feed after `done`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                |
| **Repro**              | Run any workflow with a chain (string → router → delay → preview → finish). Inspect the `runner.*` event stream on the WS bridge / sidebar feed; check both per-node input→output order and cross-node section order.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| **Root cause**         | In `runtime-runner.ts` `wireScope`, telemetry was produced by **two separate `.subscribe()` watchers** — `watchOutputPort` (subscribed to every output) and `watchInputSlot` (subscribed to every input) — in addition to the dataflow `connect()` graph. `@rx-evo` `StatefulObservable` notifies subscribers **FIFO**, and a subscribe is a (lazy) first subscriber that triggers value delivery. (1) Outputs were subscribed before inputs, so an output's telemetry fired before its input's. (2) Because inputs were watched _after_ outputs, a delayed node's downstream input received its value before the delayed source's own `output-emitted` fired — so `Delay` landed last. Data flow and event order were coupled through subscription order.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Fix**                | Removed the separate watchers entirely. Telemetry is now produced **in the dataflow path**: `tapOutputPort` / `tapInputPort` return `source.pipe(tap(emitTelemetry)).with({ meta })` and the result is `connect()`ed on the edge — so `output-emitted` / `input-received` fire as the run's values actually flow. The tap uses the `@rx-evo` typeguards (`isLoading` / `isError` / `isSuccess`) on the full `ResponseWithStatus` union, so it emits `state: 'pending'` (loading sentinel, fired by plain-Observable sources at connect), `'value'`, and `'error'` (the `@rx-evo` `ResponseError` payload) — full telemetry, no dropped states. The run is materialized by the graph itself: non-terminal nodes are driven by downstream `connect`, loops self-drive via a circular `connect`, and the runtime **subscribes only to end-node outputs** (outputs with no outgoing edge) to flush a linear graph. `wireScope` clears seeded defaults on wired ports first (BUG-2026-07-12b) and wraps only **regular** ports; **bypass** ports are `connect`ed raw (wrapping a bypass `StatefulConnection` with `pipe(tap)` would inject loading semantics and an empty initial emission). `isInactive` (disconnect/reset) is intentionally not emitted. |
| **Design flaw signal** | **Subscription order is observable event order.** A standalone `.subscribe()` for telemetry races the real dataflow because `@rx-evo` delivers a value to its first/lazy subscriber on subscribe. When event ordering carries meaning (the feed shows input→output, and the section order is the run's natural timeline), produce telemetry **on the connect path** (`pipe(tap)` with typeguards) rather than via a parallel watcher, so watching never materializes or reorders the run. Using `pipeValue(tap)` (values only) dropped error/`pending` telemetry; switching to `pipe(tap)` with `isLoading`/`isError`/`isSuccess` typeguards restores full lifecycle visibility.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Regression test**    | `packages/runtime/src/testing/workflows/port-event-order.workflow.test.ts` — linear chain `constant → delay → delay → delay`; each node's first `input-received` precedes its `output-emitted`. `packages/runtime/src/testing/workflows/delay-order.workflow.test.ts` — `string → delay(1000) → preview → finish`; delay's `output-emitted` precedes preview's and finish's (section order fixed). `packages/runtime/src/testing/workflows/signal-states.workflow.test.ts` — pending/error telemetry: async source emits `pending` → `value`; errored source emits `error`.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
